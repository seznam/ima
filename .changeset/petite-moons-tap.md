Add RTL-backed integration testing utilities to `@ima/testing-library`.

- **What?** Add the `@ima/testing-library/integration` entry point with `initImaApp`, `routeImaApp`, and `clearImaApp`. Integration tests boot the application mapped as `app/main` in the JSDOM of the Jest preset and render its pages through the application page renderer inside React Testing Library's `act`, so Testing Library queries work against the page. `routeImaApp` performs the initial navigation through IMA's `routeClientApp` and rejects fatal routing errors when the application defines no `$IMA.fatalErrorHandler`. `clearImaApp` destroys the page manager before unmounting the page and restores the timers, animation frames, and other globals wrapped during boot; Jest fake timers stay detectable by Testing Library. Shared hooks are configured under `setImaTestingLibraryClientConfig({ integration })`, and `setImaTestingLibraryServerConfig({ environment })` selects the IMA environment of unit and integration tests, `test` by default. New `create-ima-app` projects use the integration utilities.
- **Why?** Integration tests reuse the JSDOM initialized by the Jest preset instead of creating their own, render through React Testing Library, and select the configured IMA environment consistently instead of depending on `NODE_ENV` or module import order.
- **How?** Upgrade to `@ima/testing-library` 21, then follow the migration notes in the testing documentation. Replace `@ima/plugin-testing-integration` imports with `@ima/testing-library/integration`, remove `@jest-environment node` docblocks from integration suites, replace the initial `app.oc.get('$Router').route(path)` call with `routeImaApp(app, path)`, and always await `clearImaApp(app)`. Move server-time options to `setImaTestingLibraryServerConfig` and runtime hooks to the `integration` key of `setImaTestingLibraryClientConfig`, and map `^app/main$` in Jest instead of configuring `appMainPath`. Set `useFakeDictionary: false` when assertions depend on real translations, and mock `$Http` or install `fetch` in `prebootScript`, because JSDOM does not provide it. Register application listeners through `$Window.bindEventListener` or remove native listeners in their owner's teardown, since the JSDOM is shared between boots, and reuse no route names in `initRoutes` overrides, which are added to the application's routes. Suites that selected their environment through `IMA_ENV` or `NODE_ENV` must configure it explicitly; `environment: undefined` keeps the legacy resolution.
