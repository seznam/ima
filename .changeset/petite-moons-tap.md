Add RTL-backed integration testing utilities to `@ima/testing-library`.

- **What** Add the `@ima/testing-library/integration` entry point with `initImaApp`, `clearImaApp`, and tracked AOP helpers. Integration boot loads the mapped `app/main`, renders and updates IMA page views through React Testing Library, supports shared hooks under `setImaTestingLibraryClientConfig({ integration })`, and restores React roots, browser shims, timers, assertions, object-container state, and AOP hooks during cleanup. Listener cleanup only removes registrations owned by the application's `$Window` service, preserving React's document listeners across boots. The integration binding points `$PageRenderer` at the React Testing Library implementation, which transfers root ownership only after successful renders, releases owned roots, and restores the original server markup before another application uses the same Jest environment. Overlapping cleanup calls are queued so the next application cannot boot against partially destroyed state. `setImaTestingLibraryServerConfig({ environment })` defaults to `test` and is passed explicitly to `createIMAServer` without modifying process variables. New `create-ima-app` projects use the shared integration utilities.
- **Why** Integration tests can reuse the JSDOM initialized by the existing Jest preset and consistently select their configured IMA environment instead of depending on `NODE_ENV` or module import order.
- **How** Install `@ima/server` 20.1 or newer. Replace `@ima/plugin-testing-integration` imports with `@ima/testing-library/integration`, configure server-time values through `@ima/testing-library/server`, and move runtime hooks to the `integration` key of `setImaTestingLibraryClientConfig`. Because `environment` defaults to `test`, projects that selected the environment through `IMA_ENV` must pass the same value to `setImaTestingLibraryServerConfig`. Use `$Window.bindEventListener` for application-owned listeners; remove directly registered native listeners in their owner's teardown. Awaiting `clearImaApp` is recommended, but not required, because the next `initImaApp` waits for pending cleanup.
