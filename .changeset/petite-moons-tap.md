Add RTL-backed integration testing utilities to `@ima/testing-library`.

- **What?** Add the `@ima/testing-library/integration` entry point with `initImaApp`, `routeImaApp`, and `clearImaApp`. Integration tests boot the application mapped as `app/main` in the JSDOM of the Jest preset and render its pages through the application page renderer inside React Testing Library's `act`, so Testing Library queries work against the page. `routeImaApp` performs the initial navigation through IMA's `routeClientApp` and rejects fatal routing errors when the application defines no `$IMA.fatalErrorHandler`. `clearImaApp` destroys the page manager before unmounting the page and restores the timers, animation frames, and other globals wrapped during boot; Jest fake timers stay detectable by Testing Library. Shared hooks are configured under `setImaTestingLibraryClientConfig({ integration })`. New `create-ima-app` projects use the integration utilities.
- **Why?** Integration tests reuse the JSDOM initialized by the Jest preset instead of creating their own, render through React Testing Library, and keep IMA's environment resolution through `IMA_ENV` and `NODE_ENV`.
- **How?** To migrate from `@ima/plugin-testing-integration`, follow the migration notes in the testing documentation. Replace `@ima/plugin-testing-integration` imports with `@ima/testing-library/integration`, remove `@jest-environment node` docblocks from integration suites, replace the initial `app.oc.get('$Router').route(path)` call with `routeImaApp(app, path)`, and always await `clearImaApp(app)`. Remove the `environment` option; Jest sets `NODE_ENV=test`, and `IMA_ENV` selects another environment. Move other server-time options to `setImaTestingLibraryServerConfig` and runtime hooks to the `integration` key of `setImaTestingLibraryClientConfig`, and map `^app/main$` in Jest instead of configuring `appMainPath`. Set `useFakeDictionary: false` when assertions depend on real translations, and mock `$Http` or install `fetch` in `prebootScript`, because JSDOM does not provide it. Register application listeners through `$Window.bindEventListener` or remove native listeners in their owner's teardown, since the JSDOM is shared between boots, and reuse no route names in `initRoutes` overrides, which are added to the application's routes.
